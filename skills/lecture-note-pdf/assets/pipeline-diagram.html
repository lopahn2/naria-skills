lecture-note-pdf · plugin architecture

강의노트가 PDF 한 장이 되기까지

녹취록과 교재를 넣으면 교시별 서브에이전트(Sonnet)가 읽고, 메인 에이전트가 그 노트만 읽어 통합본을 쓴다. notes/와 cross.jsonl은 재사용·검색을 위해 남고, 원문·조립 중간파일은 남기지 않는다.

③ 입력 자료 — 원본, 가공 안 함
② 중간 산출물 — 재사용·누적
① 최종 산출물
④ 임시 파일 — 재사용 안 함
OKF 번들 — RAG 업로드용

왜 서브에이전트로 나누는가

8교시 녹취를 전부 메인 컨텍스트에 올리고 통합본까지 쓰면 ~210,000 토큰이 쌓여 문서 작성 단계에서 압축이 걸린다(실측). 그래서 읽기(교시별 정독)는 서브에이전트가, 쓰기(통합본)는 메인이 나눠 맡는다.

cross.jsonl은 왜 따로 있는가

교시 8개가 같은 파일에 동시에 append해도 깨지지 않는다 — 한 줄을 한 번의 write()로 쓰기 때문이다. 당일 통합본 작성엔 안 쓰지만, 여러 날짜를 넘나들 때 노트 전체를 다시 열지 않고 이 인덱스만 먼저 훑는다.

단계실행자입력출력
Phase 0 · 전처리·매칭 메인 audio/*.txt, slides/*.pdf idx_*.json, 등급 판정
Phase A · map 서브에이전트 × 교시 수
(Sonnet · effort medium)		 audio/pMM.txt + idx_*.json notes/pMM.md, cross.jsonl(append)
Phase B · reduce 메인 (대화 중인 모델) notes/*.md, cross.jsonl 파트 HTML (임시)
Phase C · 렌더·검증 메인 파트 HTML + 원본 슬라이드 out/dayNN.pdf, diagrams.json
Phase D · OKF 변환 메인 (사용자가 원할 때) ② + ③ 전체 okf/dayNN/**
