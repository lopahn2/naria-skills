# 문서 구조

## 일간 통합본 (기본 산출물)

```
표지          과정명 · 부제 · 구성(교시 수, 총 시간, 녹취 분량) · 교재 목록 · 작성 방침
하루의 흐름   오전/오후 2행 구조. 각 행에 교시별 미니 카드(교시 번호·시간·
              제목·핵심 개념 2~3개 불릿·강조 수치 하나)를 나열. 정적인
              3~4박스 추상 다이어그램 한 개로 대체하지 않는다 — 카드 하나가
              그 교시의 `## 한 문장`+`## 수치`를 압축한 것이어야 독자가
              표지만 보고 하루 전체의 지도를 얻는다.
              `template.css`의 `.flow-row-label`/`.flow-grid`/`.flow-card`
              (`.fc-n` 교시번호 `.fc-t` 시간 `.fc-title` 제목 `.fc-stat` 강조수치)
              클래스를 그대로 쓴다:
              ```html
              <p class="flow-row-label">오전</p>
              <div class="flow-grid">
                <div class="flow-card">
                  <span class="fc-n">1교시</span><span class="fc-t">37:14</span>
                  <span class="fc-title">Workflow vs Agent</span>
                  <ul><li>판단이 필요한 지점만 에이전트로</li></ul>
                  <span class="fc-stat">측정 지표 4종</span>
                </div>
                <!-- 교시 카드 반복 -->
              </div>
              ```
관통하는 한 문장   교시들을 꿰는 명제 — 이것이 통합본의 존재 이유다
목차
본문          장 = 주제 묶음 (`dayNN/outline.md`가 정한 순서. 교시와 1:1이 아닐 수 있다)
부록 A        기술 용어집
부록 B        STT 교정 대조표
꼬리말        출처 · 작성 근거 · 검증되지 않은 수치 고지
```

### "관통하는 한 문장"을 반드시 찾을 것

교시별 노트를 이어 붙이기만 하면 통합본이 아니다. 하루의 교시들이
사실 같은 문제를 다른 계층에서 반복하고 있음을 찾아 첫머리에 놓는다.

실제 사례 (1일차):

> 8교시는 서로 다른 주제처럼 보이지만 "제한된 컨텍스트 윈도우에 무엇을 어떻게
> 채울 것인가"라는 하나의 질문을 계층만 바꿔 반복한다. 하네스에서는 규칙과
> 스킬로, RAG에서는 검색된 청크로, 에이전트에서는 도구 호출 결과로 채운다.

이걸 찾으려면 전 교시의 연결 지점을 다 본 뒤에 써야 한다. 순서대로 쓰면서
마지막에 붙이려 하면 나오지 않는다. 다만 이를 위해 노트 8개 원문을 전부
다시 열 필요는 없다 — 각 노트가 이미 `## 교차 후보 ★`로 뽑아 둔 것을
`dayNN/cross.jsonl`에 모아 뒀으므로, 그것만 읽고 종합하면 된다(자세한
단계는 SKILL.md의 Phase B1 참조). 본문 작성(장 단위)은 이 종합 이후
파트별로 나눠 쓰며, 파트 작성자는 이때 정해진 연결 지도만 참고한다.

## 장(章) 구성

**장은 교시 1개를 그대로 옮긴 것이 아니라 `dayNN/outline.md`가 정한
주제 단위다.** 한 교시가 여러 주제를 다루면 여러 장으로 갈리고, 여러
교시가 같은 주제면 한 장으로 합쳐진다 — SKILL.md Phase B1 3단계 참조.
교시=장 기계적 매핑을 기본값으로 쓰지 마라. 실제로 이 재편집을
건너뛰면 "노트를 순서대로 이어 붙인 느낌"이 되어 가독성이 떨어진다.

각 장은 이 순서로:

1. `<h2>` 제목 + `<span class="tag">N교시</span>`
2. `.lead` — **이 장의 한 문장**. 무엇을 이해하고 넘어가야 하는지
3. 다이어그램 — 개념의 뼈대
4. 재구성된 설명 — **`N.1`, `N.2`... 로 번호를 매긴 소제목**(`h3`)으로
   분절한다. 장 하나에 3~7개가 적당하다. 번호 없는 `h3` 나열은 쓰지 않는다
   — 번호가 있어야 목차와 본문이 서로 대응되고, 독자가 "지금 몇 번째
   갈래를 읽고 있는지" 알 수 있다. 소제목 목록은 `outline.md`에 이미
   정해져 있으니 그대로 따른다
5. `.key` — 핵심 통찰. 강사가 강조했거나 놓치기 쉬운 지점
6. `.warn` — 함정, 흔한 오해, 주의사항
7. `.quote` — 강사 어조가 살아야 하는 곳. **장당 3개 이내**

장 시작 앞에 `<div class="br"></div>` 를 넣어 페이지를 나눈다.

## 교차 연결 박스

다른 교시의 개념이 사실 같은 원리임을 발견하면 `.lead` 또는 `.key` 박스로 명시한다.
**이것이 통합본의 최대 가치다** — 단일 교시 노트에서는 절대 보이지 않는다.

실제 사례:

- 2교시 Progressive Disclosure = 5교시 Taxonomy 다단 탐색 (조건부 로드라는 같은 발상)
- 3교시 OKF 프론트매터가 5교시 메타데이터 필터링의 복선
- 1교시 "고정된 평수" 비유가 검색 계층에서 반복됨

## 강사의 실제 예시 박스 (필수 — 생략 금지)

**노트(`notes/pMM.md`)의 `## 현장 사례`에 실제로 내용이 있는 항목은, 요약하거나
누락하지 말고 최종본에 `.example` 박스로 전부 옮긴다.** 한두 문장으로 압축한
"AI 상담사", "투자 심사" 같은 일반화는 실패다 — 강사가 든 구체적 사례(등장 인물·
수치·전개)가 살아 있어야 한다.

```html
<div class="example">
  <p class="ex-label">강사의 실제 예시</p>
  <p>은행 AICC/ARS에서 이중 결제가 발생했을 때, 상담사가 결제 취소와 보상 여부를
  어떻게 확인하는지 — 이 과정에서 Agent가 단순 FAQ 응답이 아니라 여러 시스템을
  오가며 판단해야 하는 지점이 드러난다.</p>
</div>
```

한 노트에 현장 사례가 여러 개면 박스도 여러 개다 — 하나로 합쳐서 요약하지 않는다.
어느 장(章)에도 안 맞는 사례라도 임의로 빼지 말고, 가장 관련 있는 장 끝에 붙인다.

**Phase C에서 이 박스 개수를 노트의 `## 현장 사례` 항목 수와 대조한다** (아래 "콘텐츠
완결성 검증" 참조). 수가 안 맞으면 사용자에게 확인 없이 그냥 넘어가지 않는다.

## 기술 꼭지 (용어집)

`{용어 / 정의 / 등장 교시 · 다음에 볼 것}` 3열 표.

"다음에 볼 것"에는 **교재 페이지 번호를 명시**한다. 사용자가 나중에
스스로 찾아갈 수 있게 하는 것이 목적이다. 외부 링크가 있으면 함께.

회차가 쌓이면 `glossary.md` 로 누적하되, 이미 등록된 항목은 다시 쓰지 않는다.

## STT 교정 대조표

`{녹취 표기 / 교정 / 근거}` 3열. 근거는 교재 페이지 또는 "문맥".

독자가 녹취 원본을 다시 볼 때 쓰는 지도다. 변이형을 한 행에 모은다.

## 교시 단위 노트 (사용자가 요청할 때만)

기본 산출물은 통합본이다. 교시 노트를 따로 원할 때만 만든다.

```
헤더        교시 번호 · 주제 · 길이 · 대응 교재 페이지 · 대응 신뢰도
한 문장 요약
본문
기술 꼭지
STT 교정표
```

헤더에 **대응 신뢰도**를 반드시 표시한다 (높음/낮음/없음).
매칭이 안 된 교시는 "대응 교본 없음"으로 적고 녹취만으로 작성한다 —
억지 매칭이 훨씬 해롭다.

## 보충자료 처리

슬라이드가 아닌 **완결된 문서**(리서치 노트, 아티클 등)가 들어오면
교시 매칭 대상이 아니다.

- 대응하는 교시가 있으면 **그 장에 흡수**
- 없으면 **독립 장**으로

원문이 자체 검증 한계를 밝혔으면(예: "인용 수치는 교차 검증하지 않음)
**그 경고를 반드시 노트에 살린다.** 대외 인용 전 확인이 필요하다는 것을
독자가 알아야 한다.

## 분량 기준

| 입력 | 산출물 |
|---|---|
| 교시 1개 (15~50분, 7천~2만 자) | 5~7쪽 |
| 하루 8교시 (약 5시간, 13만 자) | 35~45쪽 |

30쪽을 넘으면 한 번에 쓰지 말고 파트 파일로 나눠 쓴 뒤 `build.py` 로 조립한다.
2~3개 장씩 한 파트가 적당하다.
