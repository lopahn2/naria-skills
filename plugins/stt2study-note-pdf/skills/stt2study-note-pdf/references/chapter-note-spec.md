# 교시 노트 스펙

서브에이전트(`lecture-chapter-analyst`)가 교시마다 하나씩 만드는 중간 산출물.
`dayNN/notes/pMM.md` 에 쓴다.

**이 파일의 목적은 요약이 아니다.** 메인 에이전트가 원문 없이도 통합본을 쓸 수 있을 만큼
충분히 두꺼워야 한다. 교시당 2,000~3,500자가 적정이다. 1,000자 미만이면 실패다.

## 형식

```markdown
# NN교시 · <주제>

- 길이: MM:SS
- 대응 교본: <파일명> p.A–B  (신뢰도: 높음|낮음|없음)

## 한 문장
이 교시 전체를 관통하는 명제 한 줄. 통합본의 `.lead` 박스가 될 문장이다.

## 논지 흐름

### <소제목>
발화를 재구성한 3~5줄. 압축하지 말 것 — 메인 에이전트는 원문을 보지 못한다.
강사가 "왜" 그렇게 말했는지의 근거까지 담는다.

### <소제목>
...

## 비유

### <비유 이름>
- 발화: "원문 그대로 인용. 비유는 표현 자체가 값이라 재구성하면 죽는다"
- 설명: 무엇을 설명하기 위한 비유인가
- 시각화 제안: 어떤 다이어그램이 될 수 있는가 (2단 비교 / 흐름도 / 막대 등)

## 수치

| 값 | 맥락 | 출처 |
|---|---|---|
| 95%^10 ≈ 60% | 멀티스텝 누적 오차 | 교본 p.55 |
| 25만→100만 토큰에서 91.9%→71% | 롱 컨텍스트 정확도 저하 | 발화(벤치마크 인용) |

정확히 옮긴다. 반올림하거나 "대략"으로 뭉개지 말 것.

## 현장 사례

강사가 자기 경험으로 말한 것. 교재에 없고 가장 값지다.
"2시간 실행에 10번 추론, 그중 2~3번 이탈" 같은 것들.

## 언급 기술

| 이름 | 한 줄 정의 | 교본 페이지 | 다음에 볼 것 |
|---|---|---|---|

교본 페이지를 아는 것만 채운다. 모르면 비워 둔다 — 추측하지 말 것.

## 교본 도해 판정

| 페이지 | 제목 | 도해/텍스트 | 원본 쓸지 |
|---|---|---|---|
| p.51 | Fixed Context Length | 도해 (축 2개) | ✅ 원본 |
| p.55 | Long Running Task | 텍스트만 | ❌ 직접 그림 |

**이 표가 메인 에이전트의 슬라이드 열람 횟수를 줄인다.**
이미지 위주 페이지는 직접 렌더해서 보고 판정한다. 판정 기준:

- 표현하는 축이 2개 이상인 도해 → 원본 (다시 그리면 축을 잃는다)
- 텍스트만 / 단순 나열 → 직접 그림
- 애매하면 "확인 필요"로 두고 메인이 보게 한다

## STT 교정 후보

| 녹취 표기 | 교정 | 근거 |
|---|---|---|
| 나네스 | 하네스(Harness) | 교본 p.57 |

교본에 있으면 교본 표기가 정본. 없으면 문맥.
**강사 고유 표현과 비유는 교정 대상이 아니다** — "엔터 머신", "스킬 깎는 노인" 등은 그대로.

## 교차 후보 ★

- <개념>: <다른 교시와 연결될 것 같은 이유>

**이 필드가 가장 중요하다.** 자기 교시만 보는 에이전트가 통합본의 연결을 만드는 유일한 통로다.

판단 기준 — 다음에 해당하면 표시한다:

- 다른 계층에서 **같은 원리**가 반복될 것 같다
- 앞 교시의 개념이 여기서 **귀결**되는 것 같다
- 뒤 교시에서 **다시 나올 복선**으로 보인다
- 강사가 "아까 말씀드린 것처럼", "뒤에서 다시" 라고 명시했다

실제 사례:

```
- 다단 탐색: 현재 노드의 children만 노출하는 방식.
  2교시 Progressive Disclosure(요약만 로드 후 필요시 전체)와 동형으로 보임.
  대상만 다르고 푸는 문제가 같음 — "제한된 컨텍스트를 어떻게 쓸 것인가"

- 프론트매터 필터링: 마크다운 100만 개를 줄이려면 필터 걸 지점이 필요.
  3교시에서 OKF 표준을 권한 이유가 여기서 드러남 — 그때의 복선
```

확실하지 않아도 표시한다. 판단은 메인 에이전트가 한다.
표시가 없으면 연결은 발견되지 않는다.

## 부산물: dayNN/cross.jsonl

`## 한 문장` 과 `## 교차 후보 ★` 를 뽑아 하루 단위 jsonl 파일에 한 줄 더 남긴다.
파일이 없으면 만든다. 교시마다 한 줄:

```json
{"day": "day01", "chapter": "p03", "title": "OKF와 문서 표준", "one_line": "문서를 기계가 읽게 만드는 표준화가 검색 품질을 좌우한다", "cross": ["프론트매터 필터링: 5교시 메타데이터 필터링의 복선으로 보임", "OKF 표준: 2교시 Progressive Disclosure와 같은 문제(제한된 컨텍스트를 어떻게 쓸 것인가)"]}
```

쓰는 방법은 직접 파일을 열지 말고 스크립트를 쓴다 — 여러 서브에이전트가
**같은 파일에 동시에** 쓰기 때문이다:

```bash
echo '{"chapter":"p03","title":"OKF와 문서 표준","one_line":"...","cross":["...","..."]}' \
  | python3 $S/append_cross.py dayNN
```

한 줄을 한 번의 write()로 append하므로 동시 호출에도 안전하다(자세한 이유는
스크립트 docstring 참조). 그래서 잠금이나 별도 병합 단계 없이 그냥 밀어넣기만
하면 된다.

**왜 노트와 따로 만드는가**: 여러 날짜를 누적 처리할 때, 지난 날짜의
"관통 문장"을 다시 찾으려고 그 날짜의 노트 8개(수만 토큰)를 전부 다시 열 필요가
없게 하기 위해서다. 메인 에이전트는 날짜를 넘나드는 흐름을 찾을 때
`day*/cross.jsonl` 만 읽는다(하루당 1KB 안팎). **당일 통합본을 쓸 때는 이 파일
대신 노트 본문을 읽는다** — 비유 인용·수치·현장 사례는 여기 없다.
