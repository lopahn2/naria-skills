# 다이어그램 규칙

## 혼합 규칙 — 원본을 쓸지 직접 그릴지

| 원본 상태 | 처리 | 이유 |
|---|---|---|
| **이미 도해임** | **원본 이미지를 쓴다** | 다시 그리면 축을 잃는다 |
| 텍스트만 있음 | 직접 그린다 | 시각화 이득이 순수하게 큼 |
| 단순 나열 | 직접 그린다 + 발화 내용을 얹어 정보 추가 | 원본보다 정보가 늘어남 |
| 여러 슬라이드 통합 | 직접 그린다 | 원본에 없는 그림 |
| 교재에 없는 개념(비유 등) | 직접 그린다 | 원본이 아예 없음 |

### 원본을 다시 그리면 축을 잃는다

실제로 겪은 실패 사례. 교재의 "고정된 컨텍스트 윈도우" 도해는
세 시대의 윈도우 내부 구성을 나란히 보여주는 그림이었다.

```
Prompt          Context              Harness
─────────       ──────────           ──────────────
System Prompt   System Prompt        System Prompt
User Prompt     User Prompt          User Prompt
                Tools                Skills
                                     Tools
                                     Rules
                                     Middlewares
```

이것을 "유저 영역의 크기 변화" 막대그래프로 바꿔 그렸더니
**두 개의 축을 통째로 잃었다**:

- 하네스에서 **구성 요소 개수가 6개로 늘어난다**는 핵심
- 같은 구조를 **고정(빨강)/유연(초록)으로 색칠**한 제약 표현

게다가 해석까지 틀렸다 — "유저 영역이 다시 넓어진다"고 그렸지만
원본의 User Prompt 칸은 여전히 좁았다. 바뀐 것은 넓이가 아니라 층의 개수였다.

**판정 기준: 원본이 표현하는 축이 2개 이상이면 건드리지 않는다.**

**이 판정은 이미 규칙으로 정해져 있다 — "이미지 추출이 번거롭다"는 이유로
직접 그리기로 임의 대체하지 않는다.** 실제로 이 규칙을 알면서도 작업 편의를
위해 어긴 사례가 있었다: 노트에 `✅`(원본 사용)로 판정된 페이지를, 통합 단계에서
전부 직접 그린 SVG로 바꿔버린 것. 그 결과 2개 이상 축을 가진 도해가 전부
단순화되어 정보가 빠졌다.

그러니 원본 이미지 추출이 번거롭다는 이유만으로 이 규칙을 건너뛰려는 판단이
든다면, 그 자체가 규칙 위반이다 — 조용히 SVG로 대체하지 말고, 왜 원본을 못
쓰는지(추출 실패·이미지 손상 등 실제 기술적 사유)를 사용자에게 밝히고 확인받은
뒤에만 대체한다.

### 원본을 쓸 때의 의무

그림은 원본이, **맥락 연결은 내가** 맡는 분업이다. 원본 이미지 아래에
반드시 다음 중 하나를 붙인다:

- 해설 표 — 그림의 각 부분에 강의 발화를 매핑
- 캡션 + 문단 — 그림이 말하지 않는 것을 발화에서 채움
- "놓치기 쉬운 지점" 박스 — 그림을 잘못 읽기 쉬운 부분을 짚음

원본만 덜렁 넣는 것은 교재를 복사한 것과 다르지 않다.

## 직접 그릴 때 — 인라인 SVG 규칙

외부 라이브러리 금지. Mermaid도 쓰지 않는다(렌더러 의존).
`<svg viewBox="0 0 700 H">` 형태의 인라인 SVG를 쓴다.

```html
<figure>
<svg viewBox="0 0 700 200" width="100%" xmlns="http://www.w3.org/2000/svg"
     font-family="Noto Sans CJK KR">
  <defs><marker id="a1" markerWidth="9" markerHeight="9" refX="8" refY="3" orient="auto">
    <path d="M0,0 L8,3 L0,6 z" fill="#5f6d79"/></marker></defs>
  ...
</svg>
<figcaption>교본 p.NN 재구성 — 또는 발화 내용을 시각화</figcaption>
</figure>
```

### 필수 사항

- `font-family="Noto Sans CJK KR"` 를 **svg 요소에 명시**. 빠뜨리면 한글이 깨진다
- viewBox 가로는 700 고정 (A4 본문 폭에 맞음). 세로만 내용에 맞춰 조절
- marker id는 다이어그램마다 **고유하게**. 같은 문서에 중복되면 화살표가 사라진다
- 텍스트는 `font-size` 8~11 범위. 10 미만은 인쇄 시 읽기 어렵다

### 색 팔레트 (문서 전체 통일)

| 용도 | 색 | 비고 |
|---|---|---|
| 강조·현재 | `#0b3d5c` | 진한 남색. 제목과 핵심 박스 |
| 보조·과거 | `#4a7ba7` `#7d9cb5` | 중간 파랑 |
| 비활성 | `#a8b8c4` `#dfe6ec` | 회색 계열 |
| 긍정·해법 | `#5aa06a` `#cfe3d5` | 초록 |
| 부정·한계 | `#c25a3a` `#f0d3cc` | 주황빛 빨강 |
| 주의 | `#d99000` `#fff8e6` | 노랑 |

### 겹침 방지

렌더 후 `verify.py` 로 반드시 육안 확인. 자주 나는 사고:

- 곡선 화살표가 옆의 텍스트를 가로지름 → 화살표를 짧게 하거나 반대편으로
- `text-anchor="middle"` 인 긴 라벨이 박스를 넘침 → 줄바꿈하거나 폰트 축소
- 마지막 행의 텍스트가 viewBox 밖으로 나감 → 세로 높이를 늘림

## 어떤 그림을 그릴 것인가

강의에서 **비유**가 나오면 거의 항상 그릴 값어치가 있다.
교재에 없고, 이해를 가장 크게 돕고, 기억에 남는다.

실제 사례 — 1일차에서 다이어그램으로 만든 비유들:

- 베스트 일레븐 (11자리는 같고 명단이 다르다)
- 18평 → 50평 (제약은 같고 배치가 다르다)
- 등산 갈 때 회의록 스킬을 들고 가지 않는다
- 키 → 몸무게 → 나이로 축을 늘리는 임베딩
- 서류 전형 / 임원 면접 (2단 검색)
- 택배 상자 (LangGraph State)
- 공부 못하는 학생 / 잘하는 학생 (오픈북 시험)

수치가 나오면 그래프로 만든다 — `95%^10 ≈ 60%`, `25만 토큰 91.9% → 100만 71%`,
`100만 → 10만 → 100` 같은 것들.
